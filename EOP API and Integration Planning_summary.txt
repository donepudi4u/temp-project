EOP API Technical Overview

- Shrikanth explained the EOP capability, which expands existing logic to support other partners and integrations beyond current DApply users.
- The new lookup API will support standalone pre-qual calls using either an app key or four PII fields: last name, zip code, last four of SSN, and mobile phone number.
- The process involves performing a database lookup and then calling Synapse with a PQ re-pro value for validations and potential offer updates.

Amazon Integration Requirements

- Amazon requires a specialized integration where they use ERID instead of all four PII fields, necessitating support for both key codes and reference IDs.
- Amazon will not receive retargeting emails from Synchrony; instead, they will manage retargeting internally via quick screen checks during login or checkout.
- To facilitate this, the team must set a "suppress UP emails" custom attribute in the CDP API for Amazon while still sending payload data to CDP.

Versatile Integration Strategy

- Versatile acts as a third-party platform for multiple lenders, requiring an implementation similar to the existing DApply flow.
- For Versatile, Synchrony will send retargeting emails that include a specific lookup URL provided through a new input field in the API.
- Unlike the Amazon flow, Versatile customers will perform authentication on their own platform by providing proof fields directly in the API call.

Future API Design Considerations

- Shrikanth noted that future enhancements should allow the lookup API to return various offer types, including those from quick screen or pre-screen processes.
- The design needs to be scalable to ensure it can handle different product configurations across multiple proxies like MPQ and standalone pre-qual.
