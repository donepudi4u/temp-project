Data Management
Speaker 1, Speaker 2, and Anisha debated how to store and isolate session data in the pre-qual proof data table.
* Status Isolation: There is a concern that using the same record for both flows would allow one process to overwrite the status of another. For example, if a successful Pass One ownership check is overwritten by a failed EOP Lookup, it could trigger incorrect scheduler behavior.
* Unique Identifiers: Speaker 2 suggested using unique key IDs with suffixes (e.g., appending "EOP" to the client-ARID) to create separate database entries for each flow.
* PII Retention: Speaker 1 argued against extending the current retention period to 30 days to avoid redundant data. Instead, they discussed sourcing necessary PII from other tables like the create application data table or via network calls to the consumer DB.

Technical Risks

* What specific fields from the Pass One payload are strictly required to complete an ownership check during an EOP Lookup without storing the entire payload?
